# XXL 塔防 · 人工试玩协议（Manual Playtest Plan）

> **项目**：XXL 塔防（XXL Tower Defense）· 微信**小游戏**（mini-game，非 mini-program）
> **引擎**：Cocos Creator 3.8.8 · 视口 400×700（竖屏）· 纯触摸
> **文档角色**：人工试玩协议 + 启动说明（仅文档交付，不改任何游戏代码/脚本）
> **配套自动门**：`tests/smoke/phase5_core_loop.md`（冒烟级）、`tests/smoke/console_evidence/`（运行时 console 证据）

---

## 1. 目的与范围

本文件给**人类测试员**在真机（微信）和/或微信开发者工具中，逐项验证"能跑起来"之后那些**机器无法判定的维度**：手感（FUN/FEEL）、触控交互、UI/UX、性能、稳定性、音频、视觉。

### 1.1 已被自动化流水线验证、无需人工重复的项
| 项 | 结论 | 证据 |
|---|---|---|
| 构建完成 + 产物完整 | ✅ PASS | `pnpm deploy` 退出码 0，`build/wechatgame/` 产物齐全 |
| DevTools 编译无致命错误 | ✅ PASS | 开发者工具自动模式（端口 5000）连接成功 |
| **运行时控制台错误数 = 0** | ✅ PASS | `tests/smoke/console_evidence/*.json` → `errorCount: 0`，阈值 0（流水线 `Console errors: 0 (PASS)` 已阻断式断言） |
| Canvas 能渲染（非空） | ⚠️ 截图超时非致命 | headless 截图 8s 超时是已知通病，**忽略**；视觉以本人工试玩的截图兜底 |

> ⚠️ 自动门 PASS **只证明"能编译、能渲染、初始化不崩"**，**不等于核心玩法正确**。本人工试玩才是玩法/体验的最终判据。

### 1.2 本人工试玩聚焦
- 核心循环是否**好玩、可读、跟手**；
- 竖屏 400×700 下的 UI/触控是否舒适、无遮挡/误触；
- 真机性能（FPS / 内存）与 30 波长跑稳定性；
- 音频、视觉是否真的产出（而非静默/空白）。

### 1.3 已知平台约束（试玩中顺带留意）
| 约束 | 值 | 试玩关联 |
|---|---|---|
| 首包大小 | < 4MB（当前约 0.58MB） | 仅发布前关注，试玩不判 |
| 总内存 | < 256MB | 见 §3.4 性能项，必看 |
| 渲染 | WebGL 1.0 | 真机兼容性，留意花屏/黑块 |
| 单资产 | < 100KB | 视觉项留意大图缺失风险 |
| 触摸热区 | ≥ 44×44px | 见 §3.2；HUD 高 44px、格 64px，理论达标，需实测 |
| 视口 | 400×700 竖屏 | 边缘/窄屏死区见 §3.2/§3.3 |

## 2. 如何启动 / 真机试玩

### 2.1 前置条件
- 已安装 **微信开发者工具**（DevTools），且本机装好 Cocos Creator（仅 `pnpm cocos:open` 需要）。
- 真机试玩：手机装**微信**、与开发机在**同一网络**，或用 DevTools「预览」生成的二维码扫码。
- 勿重复执行构建链路（其他队友正在用工具链），**只需打开/试玩**即可。

### 2.2 启动方式

| 目标 | 命令 | 说明 |
|---|---|---|
| **构建 + 打开 DevTools 并跑冒烟** | `pnpm deploy` | = `scripts/deploy-wechat.mjs`：Cocos 构建 → DevTools auto 模式（端口 5000）→ 自动编译 → 采集 console 证据。完成后 DevTools 已打开本项目，**直接试玩**。 |
| **用 Cocos 编辑器打开工程** | `pnpm cocos:open` | 启动 CocosCreator.exe 加载本工程，便于在编辑器内预览/调试（非必须，DevTools 已够试玩）。 |

> 跑完 `pnpm deploy` 后 DevTools 窗口已停在本项目运行态，可直接在模拟器或真机里玩，**无需再次构建**。

### 2.3 真机试玩（手机扫码）
1. 在 DevTools 顶部工具栏选 **真机调试** 或 **预览**（前者可远程调试，后者出二维码）。
2. **真机调试 / 预览** 会生成二维码 → 用手机微信扫码，在手机上进入小游戏。
3. 要求：手机微信已登录、**与开发机同网络**（预览二维码一般也需同网；远程真机调试按工具提示）。
4. AppID 说明：本地 DevTools 试玩可用「**测试号模式**」免 AppID；真机预览/调试需项目配置**有效 AppID**（项目已带 `wx10c928d3274d2360`，若被清空则先补回或仅本地测试号试玩）。

### 2.4 关于截图超时（重要）
自动化里的 headless 截图会 8s 超时 —— **这是已知、非致命问题，直接忽略**。不要因此判定失败；视觉证据改由本人工试玩在 §5 手动截图兜底。

## 3. 试玩检查清单（Checklist）

> 勾选规则：每项独立记 **PASS / FAIL**。FAIL 须附带一句话现象描述（如"波次 12 起 FPS 掉到 22"）。

### 3.1 核心循环手感 ★（最重要）
| 检查动作 | 通过标准（PASS 长这样） | 失败信号（FAIL 即记） |
|---|---|---|
| 开局点空格子放**箭塔** | 点一下即出现箭塔，金币从 200 扣 50 | 点了没反应 / 扣错钱 / 放错格 |
| 观察敌人生成与移动 | 敌人按固定路径点逐格推进，速度合理、可读 | 敌人不动 / 穿墙 / 瞬移 / 不生成 |
| 塔自动索敌开火 | 敌入射程（箭塔 140px）塔自动开火，有弹道 | 敌在射程内塔不开火 / 弹道乱飞 |
| 弹道命中 + 敌人死亡 | 子弹命中掉血，血量归零敌人消失并掉金币 | 命中不掉血 / 敌人打不死 / 金币不涨 |
| 波次推进 1→30 | 能逐波开始、清波、进下一波，波次计数实时 +1，可到 30 波 | 波次卡死 / 计数错 / 到不了 30 |
| 经济实时更新 | 击杀奖励（basic10/fast15/tank30，含 5% 增益）、清波奖励（30+5×(波-1)）随事件跳动 | 金币不增 / 显示滞后 |
| 胜负判定 | 漏怪扣命（共 20 命），命归 0 → 失败；清完 30 波 → 胜利 | 该输不输 / 该赢不赢 / 无结算 |
| **整体好玩吗？** | 一眼看懂"我在干嘛"，节奏舒服、有策略感 | 懵 / 无聊 / 不知目标 |

### 3.2 触控交互
| 检查动作 | 通过标准 | 失败信号 |
|---|---|---|
| 点格放塔 | 点哪放哪，命中即触发 | 需点多次 / 偏移 / 不灵 |
| 塔操作菜单（选中/升级/出售） | 选中塔后升级/出售菜单**可达**、按钮可点 | 菜单点不开 / 按钮太小点不到 |
| 触摸热区 ≥44×44px | 所有可点元素实测可一次点中、无误触 | 频繁误触邻格/邻钮 |
| 边缘死区 | 400×700 顶部/底部/左右边缘的按钮都能点到（窄屏） | 边缘按钮点不到 / 被裁 |

### 3.3 UI/UX（400×700 竖屏）
| 检查动作 | 通过标准 | 失败信号 |
|---|---|---|
| HUD 可读 | 顶部 HUD（金币 / 波次# / 命数 20 / 塔选择栏）清晰可读、数值实时 | 字太小/重叠/看不清 |
| 无遮挡/裁切 | 窄竖屏下元素无重叠、无出屏裁切 | 面板互相盖住 / 元素被切 |
| 暂停/继续 | 有暂停且能恢复，状态不丢 | 暂停失效 / 恢复后错乱 |
| 开始波次按钮 | 「开始下一波」类按钮明显、可触发（准备期 15s / 间歇 5s） | 找不到开始按钮 / 点了没反应 |
| 非法放置反馈 | 在路径/占用格放置时给**明确反馈**（变红/提示），不静默吞 | 非法放置无提示、玩家困惑 |

### 3.4 性能（真机重点）
| 检查动作 | 通过标准 | 失败信号 |
|---|---|---|
| 真机 FPS | 全程流畅；**波次 >15（尤其 20–30 多实体）FPS ≥ 30** | 波次 >15 掉到 <30 / 明显卡顿 |
| 内存 | DevTools 性能面板 / 手机监视，**总内存 < 256MB** | 内存 > 256MB / 持续爬升 |
| 内存泄漏 | 跑 ≥10 波（建议完整 30 波）后帧率/内存不**渐进劣化** | 越跑越卡（疑似泄漏） |

### 3.5 稳定性
| 检查动作 | 通过标准 | 失败信号 |
|---|---|---|
| 完整/部分长跑 | 连续跑多波（建议 ≥10，最好 30）**无崩溃/无卡死** | 中途崩 / 冻屏 / 闪退 |
| 试玩中控制台错误 | 主动游玩时 DevTools console **仍 0 错误**（自动门只在加载时断言 0，互动中也要盯） | 游玩中冒出 console.error / 红字 |
| 压力操作 | 快速连放塔（spam）、连点跳波，状态不坏 | 卡死 / 金币变负 / 波次错乱 / 幽灵塔 |

### 3.6 音频（Web Audio，非 Cocos 音频模块）
| 检查动作 | 通过标准 | 失败信号 |
|---|---|---|
| 塔开火音效 | 箭/炮/减速塔开火有声音 | 开火完全静音 |
| 敌人死亡音效 | 击杀有反馈音 | 击杀无音 |
| 清波音效 | 清完一波有提示音 | 清波无音 |
| 音频实现确认 | 声音确由 **Web Audio API** 发出（非 Cocos audio 模块） | 用 Cocos 音频模块（应改回原生 Web Audio） |

### 3.7 视觉
| 检查动作 | 通过标准 | 失败信号 |
|---|---|---|
| 精灵渲染 | 塔/敌人/子弹/路径贴图正常，**无空白/缺图** | 白块 / 黑块 / 资源缺失 |
| 命中特效 | 有命中 VFX（如有粒子/飘字 `FloatingText`）且显示正常 | 特效缺失 / 卡在第一帧 |
| 对比度 | 手机亮度下颜色/文字清晰可辨 | 看不清 / 低对比糊成一片 |

## 4. 通过 / 失败判据（Gate Criteria）

### 4.1 直接 FAIL（任一命中即整体 FAIL）
- 试玩中**任何崩溃 / 闪退 / 冻屏**；
- 游玩过程中 DevTools console 出现**任何 error**（自动门只保证加载时 0，互动中也必须 0）；
- 真机 **波次 >15 时 FPS < 30**；
- HUD **不可读 / 重叠 / 出屏裁切**；
- 三种塔**任一放不了**或放了不开火；
- 波次计数**卡死 / 到不了 30**；
- 应发声时**完全静音**（且确认非静音设置问题）；
- 真机总内存 **> 256MB** 或长跑**渐进劣化**（疑似泄漏）；
- 命中非法放置却**无任何反馈**导致误操作。

### 4.2 PASS（全部满足判 PASS）
- 核心循环可完整跑通（至少 1→N，建议完整 1→30），**全程 0 控制台错误**；
- 金币 / 命数 / 波次 HUD **实时正确更新**；
- 箭塔(50)/炮塔(100)/减速塔(80) **三种均可放置且功能正常**（索敌、开火、命中、减速/ AOE 生效）；
- 触控跟手、热区达标、**无边缘死区**；
- 真机 **FPS 在波次 >15 时 ≥ 30**、内存 < 256MB、长跑不劣化；
- 音频（开火/死亡/清波）**确有声**、且走原生 Web Audio；
- 画面**无空白/缺图**、对比度在手机上可读；
- 主观评价：**一眼看懂、节奏舒服、有策略感**。

### 4.3 裁决公式
`AUTOMATED(console=0) PASS + 本人工试玩 PASS` → ✅ 整体 PASS（可宣布玩法达标）
`AUTOMATED PASS + 人工 CONCERNS/部分 FAIL` → ⚠️ 带风险，记录具体失败项后决定是否回修
`人工 FAIL（见 4.1）` → ⛔ 阻断，回对应模块修

截图与记录统一存到 **`tests/playtest/evidence/`**。

## 6. 给测试员的 3 个最该盯的点（Top Watch-outs）
1. **核心循环是否"好玩且一眼懂"**：放塔→敌人走→塔开火→命中→掉钱→进波，整条链路是否顺、是否有爽感（§3.1）。
2. **真机性能与泄漏**：波次 >15（尤其 20–30）的 FPS 与全程内存，必须 ≥30 FPS 且 <256MB、不越跑越卡（§3.4）。
3. **游玩中 0 控制台错误 + 音频真出声**：自动门只断言了加载时 0 错误，互动中也要盯 console；同时确认开火/死亡/清波音效确由 Web Audio 发出（§3.5/§3.6）。
